# Beiträge

## Fehler melden
Ein Issue mit Spielversion, Browser/Version, Betriebssystem, Schritten zum Nachstellen sowie erwartetem und tatsächlichem Ergebnis öffnen. Screenshot oder Konsolenausgabe nur ohne persönliche Daten beilegen. Sicherheitsrelevante Geheimnisse und Zugangsdaten niemals veröffentlichen.

## Änderungen vorschlagen
1. Aktuellen main-Stand prüfen und einen Feature-Branch anlegen.
2. Kleine, nachvollziehbare Änderung mit klarem Zweck machen.
3. Die eigenständige index.html und die bestehende Desktop-GUI erhalten.
4. docs/TESTS.md abarbeiten und tatsächliche Ergebnisse dokumentieren.
5. Betroffene Dokumentation und CHANGELOG.md aktualisieren.
6. Pull Request mit Beschreibung, Testnachweis, Risiken und gegebenenfalls Vorher-/Nachher-Bild öffnen.

Keine fremden Assets oder Code ohne geklärte Nutzungsrechte einfügen. KI-Unterstützung offen nennen; erzeugten Code ebenso prüfen wie manuelle Änderungen. Keine Behauptung bestandener Tests ohne Ausführung. Sachlich und respektvoll zusammenarbeiten.

Die Maintainer entscheiden über die Übernahme. Neue Funktionen für 1.2.0 nicht als bereits vorhandene 1.1.0-Funktionen dokumentieren.
